    Research references

    This catalog records the 73 references supplied on October 17, 2026, with their proposed uses for fpstreams. Topics include lazy pipelines, logical and physical plans, mixed Python/Rust/Arrow/NumPy execution, spilling groups and joins, bounded async execution, and semantic parity.

    Titles, categories, and links below follow the supplied list. Inclusion does not mean that a source has been verified, reviewed, implemented, or benchmarked. Extension marks a proposed capability that requires new functionality. It does not mean that the capability is available or scheduled. Review notes below distinguish source review from implemented and verified changes.

    Additional reference: StreamEx

    StreamEx extends Java's Stream API. The initial comparison used its cheatsheet and selected implementations in the streamex-0.8.4 tag. This supplements the original 73 entries without renumbering them. Selected code was read in StreamEx and MoreCollectors. No upstream code was executed or copied into fpstreams. The 0.9.0 release notes were also checked. They add nullness annotations and null-terminated helpers, and report a fix for filtering entries with null keys or values. The source comparison below remains pinned to 0.8.4.

    StreamEx feature fpstreams comparison and next question
    pairMap, mapFirst, mapLast, scanLeft Existing pairwise().map(...), map_first, map_last, and scan cover related uses. Check callback order and allocation costs before adding shortcuts.
    groupRuns, collapse, runLengths group_runs(key) groups equal adjacent keys; collapse(predicate, merger) supports pair predicates. These have different contracts. The unreleased Collector overload reduces runs without a raw run buffer.
    collapse(predicate, collector) Existing Rows.group_by_sorted(...).aggregate(...) covers ascending supported keys. The unreleased collapse overload covers arbitrary adjacent predicates and async pipelines through the same Collector state program. Memory depends on the Collector's state; a run needs a boundary or source exhaustion to emit.
    MoreCollectors.reducingWithZero Compare with the existing Collector.done protocol. An absorbing value requires an explicit user contract; ordinary reducers cannot safely infer early termination.
    headTail Study iterator ownership, replay, and cleanup before exposing a live tail. Existing unfold, map_accum, and Gatherer already cover many stateful transformations.

    For example, scanLeft(seed, accumulator) is a terminal operation that includes the seed in its result list. fpstreams scan(initial, function) is lazy and emits only states produced from input items. Copying the Java name would obscure that difference.

    These are API comparisons, not a claim of semantic equivalence or measured performance. The unreleased Collector overload preserves the existing binary merger form without adding a new method name. Java parallel streams do not establish fpstreams support for distributed execution, event-time windows, or watermarks.

    Review notes

    The roadmap records earlier comparisons and experiments separately. The October 18 follow-up below records the completed review scope. The six previously queued repositories received scoped, read-only analysis; experiments and implementation remain deferred.

    October 17: prefix counts and iterator boundaries

    Initial reading of reference 43's iterator recipes led to a check of fpstreams prefix operations. The Python path rejected floats only during execution, while the async path accepted them: take(2.5) emitted three items and take(float("nan")) emitted the entire finite input.

    The unreleased fix normalizes take, limit, drop, and skip counts once through the integer index protocol when constructing the operation. Both APIs accept integer-index objects and reject floats before opening a source. Integer behavior, zero-count boundaries, iterator cleanup, and existing execution paths remain subject to regression checks. No upstream implementation was copied or executed.

    Reference 45's iterator-scoping guide distinguishes owning an iterator from borrowing it for several operations. fpstreams already closes owned async iterators on early termination. This comparison preserves that default; a borrowing API remains a separate candidate. The initially attempted iterator API URL was unavailable, so the guide was reached through the documentation index instead.

    Versioned paper follow-up

    These were the initial checks on October 17. Full-paper reading was completed in the October 18 follow-up below.

    Metadata and abstracts were checked for references 2, 3, 18, and 19. Their supplied titles match the papers, including abbreviated titles for 3 and 18. These checks are not full-paper reviews.

    The streaming model and scope sections of reference 3 describe an acyclic, single-consumer compilation model with declared state. Its allocation guarantee depends on individual operators avoiding calls and allocations. For fpstreams, our inference is to evaluate fusion within proven expression paths first, while preserving observable Python callbacks, exceptions, and iterator cleanup. The paper does not establish a speedup or unrestricted fusion for this library.

    Reference 19 assumes an associative aggregate operation. A local probe using the existing reducer law checker accepted a small exact-integer sum sample and rejected the corresponding floating-point counterexample. This does not prove integer laws for arbitrary user reducers. DABA remains a candidate requiring an explicit algebraic contract; it cannot silently replace arbitrary window callbacks or change initial partial-window behavior.

    October 18: completed review and adopted changes (unreleased)

    All 25 papers in this catalog were read in full. The project, specification, and commercial references were reviewed through relevant architecture documents, public documentation, and selected core implementations. Earlier links in the roadmap received the same scoped review. This does not constitute an audit of every upstream repository or inspection of closed-source engine internals.

    The resulting changes reuse fpstreams' existing execution paths:

    • Query-wide task/file limits and task-scope limits normalize integer-index values once and reject nonintegers before resource acquisition.
    • Synchronous filter_map() removes tuple adaptation while preserving iterator boundaries. Async filter_map() uses the existing serial fusion stage. Both call the mapper once per input and discard only None.
    • Report metadata export adds a schema version, metric units, resource scope, and event limits. Plan dictionaries also carry a schema version and execution mode. These are fpstreams schemas, not OpenLineage RunEvents or executable Substrait plans.
    • Guarded Arrow comparison chains can share a selection mask, filter payload once, or count from the mask. Existing conversion, type, and source-boundary checks remain in place.
    • Spill decoding releases encoded buffers after decoding and completed decoded frames before reading the next frame.

    The adopted changes passed the complete Python checks, existing performance gates, package checks, and installed-wheel checks on standard Linux CPython 3.11–3.14. They remain unreleased; this review did not publish a new package or establish whole-application speedups.

    A synchronous cross-node fusion prototype failed performance gates and was withdrawn. The existing window_reduce() uses Two-Stacks Lite; it was not replaced with DABA and does not promise worst-case constant work per operation. Event-time windows, distributed execution, approximate aggregations, and automatic reordering of arbitrary callbacks require separate contracts and were not adopted. Offline Optuna tuning informed the Arrow mask thresholds; the research dependencies and trial records are not product dependencies.
